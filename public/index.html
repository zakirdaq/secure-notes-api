Secure Notes API

REST API for the secure note-taking task. Node 22, Express, Mongoose, MongoDB Atlas. Authentication is JWT in the Authorization: Bearer header.

Health

GET /api/healthtry it — no auth required

Auth

POST /api/auth/registerCreate a user account. Always registers with the user role.
POST /api/auth/loginReturns accessToken and the user object.
GET /api/auth/meThe signed-in user.

Notes

GET /api/notesPaginated. A user sees only their own; an admin sees everyone's.
POST /api/notesCreate a note.
GET /api/notes/:idA note not owned by the caller returns 404, not 403.
PATCH /api/notes/:idUpdate.
DELETE /api/notes/:idDelete.

Users (admin only)

GET /api/usersPaginated list. Optional ?interest= filter.
POST /api/usersCreate a user, optionally with the admin role.
GET /api/users/:idAdmin, or the user themselves.
PATCH /api/users/:idUpdate, including role changes.
DELETE /api/users/:idDelete. An admin cannot delete their own account.

Aggregations

GET /api/users/grouped-by-interests Scenario 1 — users grouped by interest, in exactly one aggregate() call. Pagination and the group total come from a $facet stage inside the pipeline. Admin only.
GET /api/posts/user/:userId Scenario 2 — one pipeline with a $lookup stage. Public, as the spec requires posts be visible to everyone.
POST /api/postsCreate a post. Requires authentication.

Pagination

Every list endpoint accepts ?page= and ?limit= and returns page, limit, total and hasNextPage alongside the data. Oversized limits are rejected rather than silently clamped.

Indexes

Four indexes beyond the mandatory _id, all declared with schema.index: users {email} unique, users {interests} multikey, notes {owner, createdAt} and posts {author, createdAt}. Admin lists sort by _id descending, which is already newest-first for monotonic ObjectIds and avoids two further whole-collection sort indexes. The repository README explains each one and lists the indexes deliberately not created.
